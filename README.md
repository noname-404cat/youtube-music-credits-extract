# シクフォニ楽曲クレジット抽出

YouTubeチャンネル シクフォニ【SIXFONIA】(`UCGMG8BNfA8gsH9Rn_d_yW2A`) の楽曲動画から、
概要欄のクレジットを抽出してCSVにする。仮実装。

## 構成

| ファイル | 中身 |
|---|---|
| `extract.py` | 概要欄・タイトルのパース処理。ネットワークに触らない |
| `fetch_and_build.py` | YouTube Data API から取得してCSVを書く。監査統計も出す |
| `fetch_extra.py` | 楽曲以外の再生リスト・ショート・各メンバーのチャンネルの取得（下の「追加の調査」） |
| `members.py` | メンバーのチャンネルのタイトル・ハッシュタグから曲名・歌唱者を取るパース処理 |
| `fixtures.py` | 実際に取得した概要欄6本。表記ゆれを原文どおり保持 |
| `test_extract.py` | 実データに対する回帰テスト |

## 使い方

APIキーは Colab の Secrets（鍵アイコン）に `YOUTUBE_API_KEY` として登録する。
ローカルなら環境変数でもよい。**キーはコミットしない。**

Colab で動かす場合、`extract.py` と `fetch_and_build.py` をノートブックにアップロードして:

```python
!python3 fetch_and_build.py --out /content/drive/MyDrive/credits.csv
```

リポジトリに置いた場合は、clone したリポジトリのルートで同じコマンドを実行する。

Colab はランタイムが切れるとファイルが消えるため、出力先は Google ドライブにする。
`--out` に前回のCSVを指定すると `video_id` をキーに統合するので、再実行しても行が重複しない。

テスト:

```
python3 test_extract.py
```

## 追加の調査

`fetch_extra.py` は `fetch_and_build.py` と同じキーで動く（Colab では Secrets の値を環境変数に入れてから実行する）。

**本家様つきの動画**（シクフォニの日常・シクフォニ歌チャレンジ）:

```
python3 fetch_extra.py honke --out honke.csv
```

`▼本家様` がある動画だけを、1曲1行で `再生リスト / 曲タイトル / 動画タイトル / 投稿日 / 曲順 / 曲数 / video_id / 動画URL`
の列で出す。曲タイトルは本家様欄の表記のまま、曲順は欄に書かれた順、曲数はその動画の曲の総数。
動画ごとの1行版（曲タイトルは ` | ` 区切り）が要るときは `--videos-out videos.csv` を付ける。
シクフォニのチャンネル以外の動画は除く。本家様欄は「敬称略」の行、注記、グループ紹介文の手前までを読む。
監査統計には、概要欄の見出し行の出現数（`▼本家様` の表記ゆれ）と、「本家様」はあるが曲が取れなかった動画が出る。

**ショート**（シクフォニ歌ってみた Shorts `PLppXIlUC-oPwMYxLewbvGWpVJGzjXVR8P`）:

```
python3 fetch_extra.py shorts --out shorts.csv
```

ショートの概要欄はハッシュタグだけで、クレジットも本家様も歌唱者も書かれていない（30本を調べて確認）。
そのため曲名だけを採る。曲名はタイトルの `【】` から採り、`【3D】` `【アニメ】` `【シクフォニ×…】` などは曲名と見なさない。
`【】` が複数あるときは最後を採って `要確認` を立てる。

**各メンバーのチャンネルの調査**（書式の規則性を見るだけで、CSVは作らない）:

```
python3 fetch_extra.py members
```

メンバーのチャンネルIDは、シクフォニの再生リストに混ざる本人の動画の `channelId` から引く（ハンドル名を当て推量しない）。
各チャンネルの公開再生リストを一覧し、対象の再生リスト（`MEMBER_TARGETS`）について、
概要欄の `◆ラベル` の分布・`▼本家様` の有無・タイトルの形を出す。いるま と みこと は再生リストを使わず、
アップロードの新しい順から配信（`liveStreamingDetails` を持つもの）を除いて調べる。

**各メンバーの曲名リスト**:

```
python3 fetch_extra.py member-songs --out member_songs.csv
```

メンバーのチャンネルには `◆ラベル` も `▼本家様` もほぼ無い（`members` で調査）ため、**曲名・歌唱者・カバー/オリジナルだけ**を
タイトルとハッシュタグから取る。絵・動画は概要欄に `◆ラベル` があるときだけ取り、無ければ空欄（要確認は立てない）。

| メンバー | 対象 |
|---|---|
| 暇72 | 再生リスト「Covered by 暇72」「声真似歌ってみた。」「銀魂×四字熟語」 |
| 雨乃こさめ | 「オリジナル曲」「歌ってみた！」「ワンコーラス」 |
| いるま | 「Original (Solo)」「Original (Group)」「Cover (Solo)」「Rap arrange (Group)」「Rap Collaboration」「Rapppp…」＋再生リストに入っていない配信以外の動画（ショート） |
| LAN | 「LAN歌ってみた」「LANオリジナル曲」「おうたのshort」 |
| すち | 「歌ってみた」 |
| みこと | 再生リストは使わず、配信以外のアップロード |

- **曲名（タイトル）:** 先頭の `【煽り】` と末尾の `【…】` を除き、最初の `／`（または ` / `）の手前。`歌ってみた` `Covered by X` は落とす。
  `[Official …]` は `メンバー - 曲名` の形、声真似シリーズは `『曲名』` `”曲名”` の中。
- **曲名（ショート）:** 3分以下の動画は、タイトルと概要欄のハッシュタグのうち、汎用タグ（`#歌ってみた` `#vtuber` `#両声類` など）
  を除いた最初のもの。汎用タグは `members.GENERIC_TAGS` で、実データで曲名でないタグが出たら足す。`曲名の出所` 列に `ハッシュタグ` と出る。
- **歌唱者:** タイトルに出るメンバー名（二人以上で歌う動画があるため）。出なければチャンネルの持ち主。`歌唱者の出所` 列に `タイトル` / `チャンネル`。
  `爆笑／キルシュトルテ × 暇72` のようにメンバー以外の名前が `×` で並ぶものは、共演者の可能性として要確認にする。
- **カバー/オリジナル:** タイトルの表記（`[Official` `【MV】` → original、`【Cover】` `歌ってみた` `Covered by` → cover）を優先し、
  無ければ再生リスト名から。どちらも無ければ要確認。
- **再生リスト外の動画（いるま・みこと）:** 曲のタイトルらしい形（`／` `歌ってみた` `Official` など）が見えないものは採らない。
  監査に「曲名が取れなかった動画」として出るので、曲かどうかを目で確認できる。
- 再生リスト経由の動画は運営が選んだ曲なので、`／` が無くてもタイトル全体を曲名にして要確認を立てる。

## 出力列

`曲名 / 曲順 / 曲数 / 投稿日 / チャンネル / タイトル / 歌ってる人 / 歌唱者は推定 / 作詞 / 作曲 / 絵 / 動画 /
category / 原曲アーティスト / video_id / 動画URL / 要確認 / 要確認理由 / raw_description`

メドレーは1曲1行に展開するので、1動画が複数行になる（`曲順` と `曲数` で見分ける）。
それ以外の動画は `曲順=1 / 曲数=1`。

抽出できなかった項目は空欄にし、`要確認` を立てて `要確認理由` に何が起きたかを書く。
`raw_description` に概要欄の原文が残るので、ルールを直したあと再抽出できる。

## 抽出対象の決め方

タイトルの文言ではなく、2つの再生リストの登録内容を正とする。

- Cover Song Playlist `PLppXIlUC-oPw8uCDchVYal9ibApaYP-4R` → `category=cover`
- Original Song Playlist `PLppXIlUC-oPw5Giv-JPWi_5DjstLk3ML2` → `category=original`

両方に登録されている動画は、先に見つかった方のカテゴリを採る。監査統計に重複本数が出る。

再生リストにはメンバー個人チャンネルの動画も入るため、チャンネルIDが
`UCGMG8BNfA8gsH9Rn_d_yW2A`（シクフォニ）の動画だけを採る。除外した本数とチャンネル名は監査統計に出る。

## 要確認と歌唱者の推定

- カバー曲の作詞・作曲が概要欄に無いのは通常のため、要確認にしない（オリジナルは要確認）。
- `歌ってる人` を全員と仮置きした場合は `歌唱者は推定` 列に「推定」と出す。要確認理由には混ぜない。

## メドレー

タイトルに「メドレー」があり、`▼本家様` 欄に2曲以上並ぶ動画は、その曲ごとに1行にする。
`曲名` は本家様欄の表記のまま（曲名と原曲アーティストの分離はしない）、`曲順` は欄に書かれた順。

## 気をつけている点

概要欄には罠がいくつかあり、素直に正規表現を書くと壊れる。

- **`◆Lyrics` は2回出てくる。** 1回目はクレジット、2回目は「※敬称略」の後に来る歌詞全文の見出し。
  敬称略より後ろのラベルは採らない。加えて、最初の1回だけを採り、値の行数と長さにも上限を置いている。
- **ラベルの綴りが揺れる。** 実例に `◆Main Animation ＆ IIlustration`（大文字アイが2つ、全角の＆）がある。
  `Illustration` の完全一致では取りこぼすので、`i`/`l` の繰り返しを許した部分一致にしている。
- **タイトルにゼロ幅文字 (U+200D) が埋まっている。** 除去しないと曲名に不可視のゴミが残る。
  ただし `T4xi DЯiver` のキリル文字のような意匠を壊すため、NFKC等の強い正規化はかけない。
- **名前とURLの区切りは全角スペース**で、名前自体が半角スペースを含む（`藤浪 潤一郎　( url )`）。
  空白全般で切ると姓だけになる。全角スペースか括弧の開始位置で切る。
- **カバー曲の作詞作曲は原曲アーティストで埋めない。** みきとP は本人が作詞作曲だが、
  THE ORAL CIGARETTES はバンド名であって作詞作曲者ではない。空欄＋要確認で保留する。
- **`◆Music&Lyrics` は作詞と作曲を兼ねる。** 両方の列に入れる。
- **`◆RAP Lyrics` はラップ部分の作詞者。** 作詞に足すが、名前に `(RAP)` を付けて曲全体の作詞者と区別する
  （カバーでもメンバーがラップを書くことが多く、原曲の作詞者と誤読されるため）。
- **ラベルと同じ行に名前が続く書き方がある。** メンバーのチャンネルの `◆Illustration　どろ　https://…`（区切りは全角スペース）。
- **複合ラベルは複数の列に入る。** `◆Vocal & Movie & Illust` は絵と動画の両方。`Illust` の略記も絵に含める。
- **`◆サムネイラスト` と `◆Animation` も絵に入れる。** 正規化で長音符が落ちるため「アニメーション」は「アニメ」で拾う。
- **本家様欄が2曲のカバーがある。** メドレーの判定は、曲数に加えてタイトルの「メドレー」で行う。
- **オリジナル曲でも `◆Music` が無いことがある。** メドレー動画に実例がある。
  再生リストの所属では判断せず、ラベルの有無で決める。

## 未確認のまま残っていること

仮実装の根拠は2026年の6本だけで、チャンネルは2022年8月開始。以下は実行してから潰す。

- 再生リストが全楽曲を網羅しているか（未登録の楽曲動画を取りこぼしていないか）
- 再生リストに他チャンネルの動画が混ざっていないか
- 2022〜2024年の概要欄が同じ書式か
- `歌ってる人` は表記が無いとき全員と仮置きする。必ず `要確認` が立つので、
  ソロ曲を6人と誤って確定させないこと
